# 操作指南(howto)

> 读者:正要动手操作的人,边看边做。
> 定位:照着做就能完成,卡住了能对照排查。

## 章节结构

| # | 章节 | 写什么 | 不写什么 |
|---|---|---|---|
| 1 | 适用场景与前提 | 操作解决什么问题;账号/版本/权限前提 | 概念科普 |
| 2 | 步骤 | 编号步骤,每步一个动作 + 预期结果 | 原理讲解 |
| 3 | 验证 | 做完后检查什么,应看到什么 | — |
| 4 | 常见故障 | 症状 → 原因 → 处理,按出现频率排序 | 全量错误码表 |
| 5 | 延伸 | 相关指南与文档链接 | — |

**必留节:2、3、4**——没有验证与故障排查的指南会把读者卡死在半路。

## 写法约束

- 每步只做一件事;预期结果紧跟动作(命令后给关键输出)
- 命令保持可复制执行;占位符用 `<尖括号>`,首次出现处说明含义
- 版本敏感的操作,在前提节钉住版本
- 故障条目统一格式:`症状 → 原因 → 处理`

## 最小骨架

```markdown
# 如何<完成某事>

## 前提
- <账号 / 权限 / 版本>

## 步骤
1. <动作>
   预期:<输出 / 界面变化>
2. <动作>
   预期:<>

## 验证
<检查动作> → 应看到 <结果>

## 常见故障
- <症状> → <原因> → <处理>

## 延伸
- <相关文档链接>
```

## 反模式

- 步骤里夹原理讲解 → 原理放延伸或单独概念文档
- "打开终端"级与"配置内核参数"级颗粒度混排 → 先定读者群再定颗粒度
- 截图代替命令 → 命令优先文本化,可复制可搜
- 只写成功路径 → 第 4 节按真实提问频率补,而不是照错误码表抄
